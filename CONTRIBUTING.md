# Руководство по внесению вклада

**Русский** | [English](./CONTRIBUTING.en.md)

Спасибо за интерес к развитию **BookSlut**! 📖✨ Здесь описано, как запустить проект, что проверить перед Pull Request и каких правил придерживаться.

---

## 🚀 Быстрый старт

**Требования:** Node.js 18+ (рекомендуется 20 или 22 LTS), npm.

1. Сделайте форк репозитория и клонируйте его:
   ```bash
   git clone https://github.com/<ваш-логин>/E-book-reader-android.git
   cd E-book-reader-android
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Запустите сервер разработки:
   ```bash
   npm run dev
   ```
   Приложение откроется на `http://localhost:3000`.

---

## 📱 Сборка Android APK локально

Нужны Node.js, **JDK 17+** и Android Studio (или установленный Android SDK).

```bash
# Собрать веб-версию и синхронизировать с Capacitor
npm run cap:build

# Открыть проект в Android Studio
npm run cap:open

# Или собрать debug APK одной командой
npm run build:apk
```

Готовый файл: `android/app/build/outputs/apk/debug/app-debug.apk`.

## 🐞 Сообщения об ошибках и предложения

Перед созданием issue проверьте, нет ли уже похожего. Используйте шаблоны:

- **Bug report**: что делали, что ожидали, что произошло. Укажите модель телефона, версию Android, тип навигации (жесты или три кнопки) и версию приложения. Скриншот или запись экрана очень помогают.
- **Feature request**: какую задачу решает идея и как вы видите её в интерфейсе.

## 🔀 Процесс создания Pull Request

1. Создайте ветку от `main`:
   ```bash
   git checkout -b feature/short-description
   ```
   Для исправлений используйте префикс `fix/`, для документации — `docs/`.
2. Внесите изменения. Один PR — одна задача.
3. Проверьте, что всё собирается без ошибок:
   ```bash
   npm run lint
   npm run build
   ```
   Эти же проверки автоматически запускает CI (`.github/workflows/ci.yml`) для каждого PR.
4. Пишите понятные сообщения коммитов в повелительном наклонении, например: `Добавить таймер сна на 90 минут` или `fix: скрыть «+» внутри сборника`.
5. Отправьте ветку и откройте Pull Request в `main`. Опишите, что изменилось и как это проверить. Для изменений интерфейса приложите скриншоты.

## ✅ Правила для кода

### Тексты интерфейса и перевод
Приложение поддерживает русский и английский. Любой новый текст на экране оборачивайте в `tr()` и добавляйте английский вариант в `src/i18n/en.ts`:

```tsx
import { tr } from '../i18n';

<span>{tr("Добавить книгу")}</span>
showToast(tr`Удалено книг: ${count}`);
```

```ts
// src/i18n/en.ts
"Добавить книгу": "Add book",
"Удалено книг: {}": "Books deleted: {}",
```

Ключ — исходный русский текст; в шаблонах подставляемые значения обозначаются `{}`. Если поменяли русский текст, поменяйте и ключ в `en.ts`, иначе перевод пропадёт.

### Нижние отступы и системная навигация
Элементы, прижатые к низу экрана, должны учитывать высоту системной навигации Android: используйте `env(safe-area-inset-bottom)` так же, как это сделано в нижней панели в `App.tsx`. Проверяйте изменения и с жестовой, и с трёхкнопочной навигацией.

### Что нельзя менять без обсуждения
- **`com.ereader.material`** (`applicationId`, `namespace`, Java-пакет). Новый ID — это для Android другое приложение: обновление поверх старой версии не установится, а книги и прогресс пользователей останутся в старой.
- **`android/app/release-key.jks` и `keyAlias`** в `build.gradle`. От них зависит, примет ли Android новый APK как обновление.
- **Ключи `localStorage`** (`ereader_view_mode`, `ereader_app_language` и др.) и **структуру IndexedDB**. Переименование сбросит настройки и данные пользователей. Если схема всё же меняется, добавьте миграцию и увеличьте `DB_VERSION`.

### Стиль
- TypeScript + React (функциональные компоненты и хуки), стили через Tailwind CSS.
- Следуйте стилю окружающего кода; не переформатируйте файлы целиком в PR с другой задачей.
- Не добавляйте новые зависимости без необходимости — объясните в PR, зачем она нужна.
